# 1.0.2 发布验证记录

日期：2026-11-27。检查对象为完整源码构建的便携候选 DeskBox.exe，程序集版本 1.0.2.0；Steam 构建不是本次发行包。

## 发现并修复的问题

首轮内置完整回归 427 项通过，但原生截图专项在深目录下抛出 PathTooLongException。原缓存目录名含完整 64 字符摘要和 32 字符 GUID；本次生成的图片路径达到 264 字符。

将新缓存目录的摘要前缀缩短为 16 字符，完整摘要仍用于索引名，逐文件内容、长度、时间和哈希校验保留，并接受旧格式缓存。原截图不改名、不修改。新增专项检查复现“旧命名超过 260 字符、原图路径仍有效”的场景，验证新副本字节与原图一致。整个应用仍不宣称任意长路径支持。

截图专项的标题定位更新为当前“截图晾衣架”，缓存污染测试通过索引中的 Folder 查找对应记录，不依赖旧目录命名。没有删除原有行为断言。

## 修复后检查

- 默认构建：固定版 TinyCC 从 C 源码生成托盘桥与任务栏保护程序，.NET Framework 编译主程序，完整构建成功。
- 内置回归：427 项全部通过，使用新隔离目录，覆盖真实文件/回收站/监视、持久化、桌面同步、窗口层级、快捷键、组件、动画逻辑和 WPF 渲染等。
- 原生截图：43 项全部通过，包含原图字节和顺序、滚轮/圆点、缓存复用/污染/编辑/索引损坏、增删重排、URI 特殊路径及深目录修复。
- 便携路径/资源：默认数据在 EXE 旁，正式桌面行为和隔离新建文件路径区分正确，两个原生资源嵌入完整。
- Explorer 原生托盘：10 项全部通过，使用自己的临时图标验证原生位图、单击、双击、右键、中键、自绘提示、通过控制中心重排、Explorer 顺序改变、恢复及临时图标移除。未替用户点击第三方应用菜单。

全局快捷键和桌面层级测试在其他 rushbin 实例退出后运行；测试前备份正式数据，结束后按原启动方式恢复正式实例。既有个人配置和截图没有用于发行包。

## 复现与边界

入口为 scripts/test-release.ps1，截图/便携路径探针位于 scripts/tests；内置回归随 DeskBox.cs 和 native 源文件提供。托盘检查入口为 --control-check 下的 tray-model-self-test，详见 docs/BUILD.md。

托盘实测环境为 Windows 11 25H2 26200.9974，对应模块的 CodeView 签名在 native/TrayModelBridge.c 中严格匹配。不同签名在调用固定入口前返回不支持；这一分支本次做源码核对，没有冒充其他 Windows 版本的实机验证。

没有完成多机器、多屏/全部 DPI、Windows 登录冷启动、真实断网/配对和所有硬件控制、照片应用内物理左右键/首尾计数验收。WPF 生成的 PNG 不代表完整实时 DWM 合成效果；测试调用原生接口也不等于完成物理鼠标输入验证。
